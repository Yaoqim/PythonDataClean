#### 3.1 资讯文章

**数据特征**：半结构化，1000-100000 条，复杂的文本和多源数据

**业务字段清单**：article_id, title, content, author, publish_time, source, category, tag, view_count, comment_count, keyword, is_reprint

**业务核心字段**：article_id(主键), title, content, publish_time, source, category

##### 字段详细说明表

| 英文字段名    | 中文名   | 来源性质 | 处理方式                                  | 说明                 |
| ------------- | -------- | -------- | ----------------------------------------- | -------------------- |
| article_id    | 文章 ID  | 原始     | 保留纯字母数字                            | 文章唯一标识         |
| title         | 标题     | 原始     | 去特殊字符、统一编码、截断 200 字         | 核心标题             |
| content       | 内容     | 处理后   | 去 HTML 标签、广告、文末推广、连续换行    | 正文内容，需详细清洗 |
| author        | 作者     | 原始     | 去特殊符号，缺失填充"佚名"                | 作者信息             |
| publish_time  | 发布时间 | 处理后   | 相对 → 绝对时间，统一 YYYY-MM-DD          | 可能为相对时间       |
| source        | 来源     | 原始     | 规范化来源，建立标准库                    | 媒体来源             |
| category      | 分类     | 处理后   | 多值分解、规范化分类树                    | 新闻分类             |
| tag           | 标签     | 处理后   | String 分解为 Array、去重、规范化、≤15 个 | 文章标签             |
| view_count    | 阅读量   | 处理后   | 去单位，换算整数，检测异常值(999999)      | 互动数，需检测异常   |
| comment_count | 评论数   | 处理后   | 去单位，转整数                            | 评论计数             |
| keyword       | 关键词   | 新增     | 从 content 自动提取或规范化               | 文本关键词库         |
| is_reprint    | 是否转载 | 新增     | 标题相似度>90%标记(0/1)                   | 区分原创和转载       |

##### 特殊字段处理说明

**1. 转载重复检测**

- 若 parent_comment 存在性检查失败，执行 30% 的准确度的渐进
检测方式：
  1. 标题相似度 > 90% 标记为转载
  2. 内容相似度 > 85% 标记为转载
  3. 保留首发源，备份其他版本

**2. 文本污染清洗**

需去除的污染内容：

- HTML 标签和脚本
- 文末推广段落
- 广告链接（超过 30%标记 marketing）
- 无关段落和水印

**3. 分类和标签规范**

- 若 parent_comment 存在性检查失败，执行 30% 的准确度的渐进
Category规范化：
  原始: "科技 > 互联网" 或 "科技,互联网"
  处理后: "科技>互联网" (用">"分隔)

Tag规范化：
  分解多值："python,AI,机器学习" -> ["python", "AI", "机器学习"]
  去重、规范化、限制≤15个

**常见问题与清洗方案**：

##### 分步骤清洗流程

**第一阶段：去重与文章有效性验证**

| 问题类型        | 具体表现               | 清洗方案                                                     | 执行步骤                                                                                                | 无法清洗处理                                   |
| --------------- | ---------------------- | ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------- | ---------------------------------------------- | ----------------------------------------------------- |
| 重复文章        | 同一文章内容不同源发布 | 按 article_id 去重或按文章相似度>90% 标记转载                | 1. 方案一：按 article_id 分组去重 2. 方案二：打乐算法算文本相似度 3. 保留最旧的版本 4. 标记"is_reprint" | 相似度 70-90% 之间 → 标记"reprint_suspicious"  |
| article_id 缺失 | 文章无唯一标识         | **补充策略**：由(source, title, publish_time)组合生成哈希 ID | 1. 组合关键字段 2. MD5 哈希生成 3. 检验唯一性 4. 标记"id_generated"                                     | 组合字段不完整 → 标记"critical_missing" → 删除 |
| 文章无效        | 仅为剪掉或死链接       | 检测是否是改写稿、广告页、死链                               | 1. 检测文章长度 2. 检测内容程度 3. 检测外部链接比例 4. 标记无效                                         | 正文内容>200 字且汉字比>70%                  | 仅为所晓/改写 → 标记"invalid_article" → 上传死链 1 库 |

**第二阶段：文本清洗与内容补充**

| 问题类型      | 具体表现                                                     | 清洗方案                                                                                      | 执行步骤                                                                            | 准确性评估                    | 无法清洗处理                                                   |
| ------------- | ------------------------------------------------------------ | --------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- | ----------------------------- | -------------------------------------------------------------- |
| 文本污染      | HTML 标签、文末推广、广告、无关段落                          | 分步清洗：① BeautifulSoup 去 HTML 标签 ② 正则关键词匹配去广告 ③ 去第三方推广篇 ④ 检测文末推广段 | 1. HTML 解析 2. 匹配清除广告特征词 3. 正则删除外部重定向 URL 4. 验证正文>0          | 清洗后正文>200 字且污染比<20% | 全是污染 → 标记"content_invalid" → 删除                        |
| 文章过短      | 正文<50 字或仅为摘要                                         | 检测并标记，转载/摘要待删除                                                               | 1. 计算清洗后正文字数 2. <50 字标记"summary_only" 3. 检查是否有正文截断 4. 批量标记删除 | 是否正文有重要信息          | 正文<50 字 → 标记删除或审核                                      |
| 广告植入/推广 | 文中嵌入推广链接、商品推介                                   | 检测外部链接比例，>30% 标记 marketing_ratio_high                                              | 1. 正则匹配外部链接 2. 计算链接比例 3. 推广词检测 4. 检测推广内容比例 5. 标记异常 | 推广内容比例<20% 为正常       | 推广比>30% → 标记"marketing_ratio_high" → 根据业务判断 |
| 分类不规范    | 多个分类混在一起或格式不一（"科技,互联网" vs "科技>互联网"） | 按分类库映射规范化，准确使用">"作分隔                                                         | 1. 检测分类数量 2. 按分类库匹配 3. 规范化并检查有效性 4. 标记来源及处理方式             | 匹配成功率                      | 无法匹配 → 标记分类未知并保留原值                                                 |
| 标签不规范    | 标签重复、大小写不一、超过限制                                 | 按标签库去重，需要标准化、限制<=15 个                                                   | 1. 去重处理 2. 统一大小写 3. 按标签库匹配规范化 4. 超过 15 个删除低优先级 5. 标记修复 | 标签匹配成功率>=90%           | 无法匹配 → 删除或标记                                                |

**第三阶段：时间与数值异常检测**

| 问题类型                      | 具体表现                             | 清洗方案                                                      | 执行步骤                                                          | 异常判定标准                  | 无法清洗处理                           |
| ----------------------------- | ------------------------------------ | ------------------------------------------------------------- | ----------------------------------------------------------------- | ----------------------------- | -------------------------------------- |
| 发布时间异常                  | 时间晚于当前时间、格式混乱、相对时间 | 时间范围校验：publish_time <= 当前时间，格式转换为 YYYY-MM-DD | 1. 解析时间格式 2. 相对时间转绝对 3. 范围校验 4. 格式统一 5. 标记异常 | publish_time <= now()         | 时间不合理 → 标记"time_invalid" → 删除 |
| view_count/comment_count 异常 | 默认值 999999、负数、超出上限        | 范围检验(0-1000000000)，默认值标记"view_count_default"        | 1. 检验范围 2. 检测是否是默认填充值 3. 异常则标记 4. 记录异常统计 | 0 <= view_count <= 1000000000 | 无法修正 → 标记"engagement_unknown"    |
| author 缺失                   | author 为空或 NULL                   | 填充"佚名"(指作者未署名)                                      | 1. 检验是否缺失 2. 填充"佚名" 3. 批量标记来源                     | author 填充成功               | author 缺失且不填充 → 标记待补充       |

**第四阶段：文本清洗与编码处理**

| 问题类型              | 具体表现         | 清洗方案                                            | 执行步骤                                                                      | 验证方式                     | 无法清洗处理                             |
| --------------------- | ---------------- | --------------------------------------------------- | ----------------------------------------------------------------------------- | ---------------------------- | ---------------------------------------- |
| 正文/标题乱码         | 正文或标题出现乱码 | 使用 chardet 检测原始编码 → 重新解码为 UTF-8 → 验证 | 1. chardet 检测编码 2. 按检测编码解码 3. 验证汉字可读性 4. 失败则尝试其他编码 | 解码后汉字可读且编码准确率>90% | 编码无法识别 → 标记"encoding_error" → 删除 |
| 正文超长              | 超过 50000 字    | 截断至 50000 字，标记"content_truncated"            | 1. 检测长度 2. >50000 则截断 3. 保存原始长度 4. 存储备份                  | 截断是否损失关键信息         | 手工评估是否保留全文                     |
| 摘要/外部链接污染 | 正文末尾        | 正则匹配重定向链接、尾部污染、推广信息 → 删除         | 1. 正则检测外部链接 2. 污染匹配 3. 推广信息 → 删除                         | 不能保留 → 手工检查          |

##### 缺失值补充策略汇总

**分级补充方案**（按准确性从高到低）：

| 缺失字段         | 一级补充(>95%)    | 二级补充(70-95%)       | 外部补充(<70%) | 补充失败处理                                   |
| ---------------- | ----------------- | ---------------------- | -------------- | ---------------------------------------------- |
| **article_id**   | 源系统 article_id | 生成(source+title)哈希 | 序列号         | **无法补充** → 删除                            |
| **title**        | 源系统标题        | 提取第一段落             | URL 标题       | **无法补充** → 删除                            |
| **content**      | 源系统正文        | 提取第一或最長段       | RSS 摘要       | **标记 content_incomplete** → 批量判断是否保留 |
| **author**       | 源系统作者        | HTML 提取              | 填充"佚名"     | **标记 author_anonymous**                      |
| **publish_time** | 源系统时间戳      | 相对时间转绝对         | 填充 HTTP 眉头 | **标记 time_uncertain**                        |
| **category**     | 源系统分类        | 按分类库映射           | 从 tag 推断    | **批量判断是否保留**                           |

**准确性评估指标**：

- 若 parent_comment 存在性检查失败，执行 30% 的准确度的渐进
article_quality = Σ(field_weight × field_confidence) / Σfield_weight

字段权重分配：
  article_id: 1.0 (必填)
  title: 1.0 (必填)
  content: 0.9 (关键)
  author: 0.5 (可选)
  publish_time: 0.8 (重要)
  category: 0.6 (辅助)
  tag: 0.4 (可选)

判定标准：
  >= 85%: 优质文章，可直接使用
  >= 70%: 良好文章，可使用但需标记
  >= 50%: 一般文章，需要审核
  < 50%: 低质文章，建议删除
