##### 二、业务核心字段清洗需求与处理正流程

**第一阶段：去重与关键字段验证**

| 问题类型        | 具体表现                                             | 清洗方案                                                                            | 执行步骤                                                                        | 无法清洗处理                                    |
| --------------- | ---------------------------------------------------- | ----------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- | ----------------------------------------------- |
| 重复评论        | 相同 comment_id 或(product_id, user_name, content)重复 | 按 comment_id 去重，或按(product_id, user_name, comment_content)组合判断完全重复；**二级评论**：允许相同内容但不同 parent_comment_id（回复上下文不同）| 1. 按 comment_id 分组统计 2. 检测组合重复 3. 一级评论保留最新，二级评论每个父评论可重复 | 若无 comment_id，按组合去重，标记"id_generated" |
| comment_id 缺失 | 评论无唯一标识                                       | **补充策略**：由(product_id, user_name, comment_content, comment_time, comment_level, parent_comment_id)组合生成哈希 ID | 1. 二级评论必须包含 parent_comment_id 2. 生成哈希值 3. 检验唯一性 4. 标记"id_generated"  | 组合字段也缺失 → 标记"critical_missing" → 删除  |
| product_id 缺失 | 评论无关联商品                                       | **补充策略**：二级评论无需 product_id（继承父评论）；一级评论从相邻推断或标记缺失                         | 1. 判断 comment_level 2. 二级评论跳过此步 3. 一级评论查询相邻 4. 标记来源       | 无法推断 → 标记"product_id_unavailable" → 删除  |
| user_name 缺失    | 匿名用户评论                                         | **补充策略**：填充"anonymous_user"                        | 1. 检查 user_name 是否存在 2. 缺失则填充"anonymous_user"                   | 保留为"anonymous_user"                                |
| parent_comment_id 缺失(二级) | 二级评论不指向父评论 | **验证策略**：检查 parent_comment_id 是否存在有效的一级评论；形成循环引用检测 | 1. 查询 parent_comment_id 是否存在 2. 检查回环 3. 推断或匹配父评论 4. 标记来源 | 所属一级评论不存在 → 标记"orphan_comment" → 删除 |

**第二阶段：字段内容清洗与补充**

| 问题类型 | 具体表现                                    | 清洗方案                                                         | 执行步骤                                                       | 准确性评估                         | 无法清洗处理                                  |
| -------- | ------------------------------------------- | ---------------------------------------------------------------- | -------------------------------------------------------------- | ---------------------------------- | --------------------------------------------- |
| 文本污染 | HTML 标签、表情符号、@用户、URL 链接        | 去 HTML 标签 → 去表情 → 去@用户 → 去 URL 链接                    | 1. BeautifulSoup 去 HTML 2. 正则去 emoji 3. 去@提及 4. 去链接  | 清洗后文本长度>0 且可读            | 全是污染内容 → 标记"content_invalid"          |
| 评论过短 | comment_content<10 字                       | 检测并标记，可选删除                                             | 1. 计算文本长度 2. 标记"content_too_short"                     | 是否有实际意义(如"好""赞"也有价值) | 根据业务规则决定删除或保留                    |
| 垃圾评论 | 刷屏重复字符（"哈哈"×50）、纯广告、无关评论 | **检测模式**：① 连续重复字符>80% ② 包含推广链接 ③ 与商品完全无关 | 1. 检测重复率 2. 识别广告关键词 3. NLP 相关性检测 4. 标记/删除 | 识别准确度需>85%                   | 无法确定 → 标记"spam_suspicious" → 待人工审核 |

**第三阶段：异常值检测与修正**

| 问题类型           | 具体表现                           | 清洗方案                                     | 执行步骤                                | 异常判定标准                                        | 无法清洗处理                           |
| ------------------ | ---------------------------------- | -------------------------------------------- | --------------------------------------- | --------------------------------------------------- | -------------------------------------- |
| 评分异常           | 6 分、0 分、负数、非整数           | 范围检验(1-5) → 超出范围标记"rating_invalid" | 1. 检验范围 2. 转整数 3. 标记异常       | 标准范围 1-5，仅限整数                              | 无法确定正确值 → 标记"rating_unknown"  |
| helpful_count 异常 | 负数、超百万                       | 范围检验(≥0, <1000000)                       | 1. 检验范围 2. 异常值标记               | 标准范围 0-1000000                                  | 无法修正 → 标记"helpful_count_invalid" |
| 时间异常           | 时间早于商品上架时间或晚于当前时间 | 比对 comment_time 与 product listing_time    | 1. 比对两个时间 2. 范围校验 3. 标记异常 | comment_time >= product.listing_time 且 <= 当前时间 | 时间无法修正 → 标记"time_invalid"      |

**第四阶段：文本清洗与编码处理**

| 问题类型 | 具体表现             | 清洗方案                           | 执行步骤                                             | 验证方式             | 无法清洗处理                               |
| -------- | -------------------- | ---------------------------------- | ---------------------------------------------------- | -------------------- | ------------------------------------------ |
| 乱码文本 | 评论内容出现乱码字符 | chardet 检测编码 → 重新解码 → 验证 | 1. chardet 检测 2. 重新解码 3. 验证可读性            | 解码后无乱码且可读   | 编码无法识别 → 标记"encoding_error" → 删除 |
| 超长评论 | 超过 10000 字        | 截断至 10000 字                    | 1. 检测长度 2. 超长则截断 3. 标记"content_truncated" | 截断是否损失关键信息 | 自行评估是否需要全文保留                   |

##### 缺失值补充策略汇总

**分级补充方案**（按准确性从高到低）：

| 缺失字段          | 一级补充(高置信度>95%) | 二级补充(中置信度 70-95%)                | 外部补充(低置信度<70%) | 补充失败处理                                   |
| ----------------- | ---------------------- | ---------------------------------------- | ---------------------- | ---------------------------------------------- |
| **comment_id**    | 源系统原始 ID          | 生成(product_id + user_name + content)哈希 | 使用内部序列号         | **无法补充** → 删除记录                        |
| **product_id**    | 源系统 product_id      | 查询相邻评论推断                         | 无法推断               | **标记 product_id_unavailable** → 删除         |
| **user_name**     | 源系统 user_name           | 脱敏用户名称              | 填充"anonymous_user"      | **标记 user_name_anonymous** → 保留                 |
| **rating_score**  | 原始评分               | 从其他相邻评论推断平均值                 | 无法推断               | **标记 rating_unknown** → 留空或使用平台平均分 |
| **comment_time**  | 源系统时间             | 相邻评论推断                             | 使用爬取时间           | **标记 time_unknown** → 使用爬取时间           |
| **parent_comment_id(二级专用)** | **N/A(一级此字段为NULL)** | 从每一级评论查询推断 | 无法推断 | **标记 orphan_comment** → 删除 |

**准确性评估指标**（评论质量评分）：

准确性评分公式：
  comment_quality_score = \sum (field_weight × field_confidence) / \sum field_weight

其中：
  - field_weight：字段重要性权重
    * comment_id: 1.0 (必填)
    * product_id: 1.0 (必填)
    * user_name: 0.7 (重要) -> **脱敏用户名称**
    * rating_score: 0.8 (重要) -> **一级评论可有**；**二级评论不需要**
    * comment_content: 0.9 (核心)
    * comment_time: 0.6 (可选)
    * helpful_count: 0.3 (可选) -> **二级评论易提取回复数**
    * parent_comment_id: 0.5 (二级专用) -> **一级评论为NULL**
    * comment_level: 0.4 (区分一二级)
  - field_confidence：每个字段的置信度(0-100%)

判定标准：
  score >= 80%：优质评论，可直接使用
  score >= 60%：良好评论，可使用但需标记
  score >= 40%：一般评论，需要审查
  score < 40%：低质评论，不建议使用或删除

二级评论需有效 parent_comment_id 及 parent 评论本身有效，孤立二级评论（orphan_comment）会产生 10-30% 的分数扣减。
