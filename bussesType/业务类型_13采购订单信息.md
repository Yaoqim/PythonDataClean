### 十一、采购订单信息

**数据特征**：结构化（JSON/CSV），1000-100000 条/批次，中等难度

**业务字段清单**：order_id, order_no, purchase_date, supplier_id, supplier_name, item_id, item_name, order_qty, unit_price, total_amount, currency, status, delivery_date, received_date, payment_status

**业务核心字段**：order_id(主键), supplier_id, item_id, order_qty, unit_price, total_amount, status

##### 字段详细说明表

| 英文字段名       | 中文名       | 来源性质 | 处理方式                                        | 说明                      |
| --------------- | ----------- | -------- | ----------------------------------------------- | ------------------------- |
| order_id        | 订单系统 ID  | 原始     | 去特殊字符、保留纯字母数字                      | 采购系统内部唯一标识      |
| order_no        | 订单编号    | 原始     | 规范化编号格式(YYYYMMxxxx)                      | 采购订单号                |
| purchase_date   | 采购日期    | 处理后   | 统一格式 YYYY-MM-DD                             | 订单创建日期              |
| supplier_id     | 供应商 ID   | 原始     | 验证与供应商主表关联                            | 供应商唯一标识            |
| supplier_name   | 供应商名    | 原始     | 去特殊字符、标准化、建立供应商库                | 供应商官方名称            |
| item_id         | 物料 ID     | 原始     | 保留纯字母数字、验证与物料库关联                | 采购物料的唯一标识        |
| item_name       | 物料名      | 原始     | 去特殊字符、统一编码、建立物料库                | 物料名称描述              |
| order_qty       | 订单数量    | 处理后   | 去单位、转整数、检测异常值                      | 采购数量(件)              |
| unit_price      | 单价        | 处理后   | 去货币符号、转 float、2 位小数、多币种转 RMB   | 单位价格                  |
| total_amount    | 采购总额    | 处理后   | 去货币符号、转 float、校验(qty*unit_price)      | 订单总金额                |
| currency        | 货币代码    | 新增     | 标记原始货币(CNY/USD/EUR 等)                    | 结算货币类型              |
| status          | 订单状态    | 处理后   | 规范化为: 已下单/已发货/已收货/已结算           | 订单当前状态              |
| delivery_date   | 预计送达    | 处理后   | 统一格式 YYYY-MM-DD、比对 purchase_date         | 约定交货日期              |
| received_date   | 实际收货    | 处理后   | 统一格式 YYYY-MM-DD、比对 delivery_date         | 实际收货日期              |
| payment_status  | 付款状态    | 新增     | 规范化为: 未付款/部分付款/已付款/已超期         | 付款状态标记              |
| is_cleaned      | 是否已清洗  | 新增     | 清洗标记(0/1)                                   | 数据清洗标记              |
| abnormal_tag    | 异常标记    | 新增     | 异常标记(price_invalid/qty_invalid/status_error/currency_error/normal) | 异常原因分类 |

##### 特殊字段处理说明

**1. 采购金额验证与货币转换**

- 若 parent_comment 存在性检查失败，执行 30% 的准确度的渐进
Amount Verification:
  total_amount = order_qty * unit_price ± 1%
  偏差超过 1% 标记 "amount_mismatch"
  
Currency Conversion:
  识别原始货币符号或代码(USD/EUR/CNY)
  按汇率表转换为人民币(若需要)
  记录到 currency 和 original_amount

**2. 订单状态流转**

- 若 parent_comment 存在性检查失败，执行 30% 的准确度的渐进
Status Workflow:
  已下单 -> 已发货 -> 已收货 -> 已结算
  检测非法流转(如: 已收货 -> 已下单)
  时间逻辑: purchase_date < delivery_date < received_date

**3. 供应商与物料的两维关联**

- 若 parent_comment 存在性检查失败，执行 30% 的准确度的渐进
Supplier-Item Mapping:
  需验证: (supplier_id, item_id) 的历史供应关系
  新供应商供应新物料需标记 "new_supplier_item_pair"
  价格异常: 相同物料不同供应商价格差异 > 30% 标记异常

##### 新增标记字段

| 字段名              | 类型   | 用途                                                    |
| ------------------- | ------ | ------------------------------------------------------- |
| original_amount     | 数值   | 原始采购金额(未转换前)                                  |
| amount_calc_diff    | 数值   | 计算偏差率((total_amount - qty×unit_price)/total_amount)|
| days_to_delivery    | 数值   | 下单到送达的天数差                                      |
| payment_overdue_days | 数值  | 超期天数(received_date - payment_deadline)              |
| clean_time          | 时间   | 清洗完成时间                                            |

**常见问题与清洗方案**：

##### 分步骤清洗流程

**第一阶段：去重与订单有效性验证**

| 问题类型     | 具体表现              | 清洗方案                                                     | 执行步骤                                                            | 无法清洗处理                                 |
| ------------ | --------------------- | ------------------------------------------------------------ | ------------------------------------------------------------------- | -------------------------------------------- |
| 订单重复     | 同一订单多次抓取      | 按 order_id 或 order_no 去重，保留时间戳最新的版本           | 1. 分组统计重复 2. 比较 update_time 3. 保留最新                     | 无法区分 -> 标记 "possible_duplicate"      |
| order_id 缺失| 无唯一标识            | **补充策略**：由(supplier_id, order_no, purchase_date)生成哈希 ID | 1. 生成 MD5 2. 检验唯一性 3. 标记"id_generated"                    | 核心字段缺失 -> 标记"critical_missing" -> 删除 |
| item_id 缺失 | 物料无关联             | **补充策略**：查询物料库by item_name，或标记缺失              | 1. 精确/模糊匹配 item_name 2. 取得 item_id 3. 标记来源              | 物料库无匹配 -> 标记"item_unavailable" -> 待审核 |

**第二阶段：字段内容标准化与关联验证**

| 问题类型      | 具体表现                           | 清洗方案                                                   | 执行步骤                                                      | 准确性评估                 | 无法清洗处理                           |
| ------------- | ---------------------------------- | ---------------------------------------------------------- | ------------------------------------------------------------- | -------------------------- | -------------------------------------- |
| 金额不匹配    | total_amount ≠ qty * unit_price    | 计算偏差率，< 1% 自动修正，> 1% 标记异常                    | 1. 计算理论金额 2. 比对实际 3. 偏差分析 4. 标记异常            | 偏差控制在 < 1%            | 偏差 > 5% -> 标记"amount_error" -> 审核 |
| 状态异常      | 状态流转非法(已收 -> 已下)          | 检测状态合法性，校验时间顺序                                 | 1. 验证状态值 2. 时间序列检验 3. 标记非法流转                 | 状态流转 100% 合法         | 无法确认 -> 标记"status_uncertain"     |
| 货币不规范    | "¥" / "RMB" / "CNY" 混存         | 识别货币类型，统一转换为代码格式(USD/EUR/CNY)               | 1. 正则识别 2. 规范化为代码 3. 标记原始值                     | 转换准确率 > 99%           | 无法识别 -> 标记"currency_unknown"     |
| 供应商价格异常| 相同物料 A 供应商 10 元 B 供应商 20元 | 统计同物料不同供应商价格差异，> 30% 标记异常                | 1. 按 item_id 分组 2. 计算价格差异率 3. 标记可疑            | 差异在 30% 内为正常        | 差异 > 50% -> 标记"price_outlier"     |

**第三阶段：异常值检测与时间验证**

| 问题类型       | 具体表现              | 清洗方案                                           | 执行步骤                                          | 异常判定标准               | 无法清洗处理                      |
| -------------- | --------------------- | -------------------------------------------------- | ------------------------------------------------- | -------------------------- | --------------------------------- |
| 数量异常       | qty <= 0 或超百万      | 范围检验(0 < qty < 1000000)，超出标记异常          | 1. 检验范围 2. 检测是否默认值 3. 标记异常         | 0 < qty < 1000000         | 无法修正 -> 标记"qty_invalid"  |
| 价格异常       | unit_price <= 0       | 价格 > 0，超出品类价格范围标记                     | 1. 范围检验 2. 同类参考价 3. 标记异常             | unit_price > 0             | 价格 < 0 -> 标记"price_invalid" |
| 日期异常       | delivery_date < purchase_date | 日期逻辑校验                              | 1. 时间大小比对 2. 天数差合理性检验 3. 标记异常  | purchase_date < received_date | 日期不合理 -> 标记"date_error" |

**第四阶段：文本清洗与编码处理**

| 问题类型     | 具体表现              | 清洗方案                              | 执行步骤                                                 | 验证方式           | 无法清洗处理                       |
| ------------ | --------------------- | ------------------------------------- | -------------------------------------------------------- | ------------------- | ---------------------------------- |
| 供应商名乱码 | 供应商名含乱码字符    | chardet 检测编码 -> 重新解码 -> 验证  | 1. chardet 检测 2. UTF-8 重新编码 3. 验证可读性          | 解码后汉字可读     | 编码无法识别 -> 标记"encoding_error" |
| 物料名特殊字符 | 物料名含"❌""⚠️"等 | 去除特殊字符和 emoji，保留中英文数字  | 1. 检测 emoji 2. 删除特殊符号 3. 验证文本长度 > 0        | 清洗后可读且有意义 | 全是特殊字符 -> 标记"content_invalid" |

##### 缺失值补充策略汇总

**分级补充方案**（按准确性从高到低）：

| 缺失字段        | 一级补充(>95%)           | 二级补充(70-95%)       | 三级补充(<70%)  | 补充失败处理                |
| --------------- | ----------------------- | ---------------------- | --------------- | --------------------------- |
| **order_id**    | 源系统 ID               | 生成(order_no)哈希     | 序列号          | **无法补充** -> 删除        |
| **item_id**     | 官方物料库代码          | 物料名模糊匹配         | 分类代码        | **无法补充** -> 待人工审核  |
| **supplier_id** | 供应商库记录 ID         | 供应商名查询           | 无法补充         | **无法补充** -> 标记待补充  |
| **unit_price**  | 采购订单原始价           | 历史供应价平均         | 品类参考价      | **标记 price_reference**    |
| **delivery_date** | 源系统约定送达          | 采购周期推算           | 无法补充         | **标记 date_estimated**     |

**准确性评估指标**：

- 若 parent_comment 存在性检查失败，执行 30% 的准确度的渐进
order_quality_score = Σ(field_weight × field_confidence) / Σfield_weight

字段权重分配：
  order_id: 1.0 (必填)
  item_id: 1.0 (必填)
  supplier_id: 0.9 (关键)
  order_qty: 0.9 (关键)
  unit_price: 0.9 (关键)
  total_amount: 0.8 (重要)
  purchase_date: 0.7 (重要)
  status: 0.6 (辅助)

判定标准：
  >= 85%: 数据完整，可直接使用
  >= 70%: 数据良好，需标记补充字段
  >= 50%: 数据一般，需人工审核
  < 50%: 数据不完整，不建议使用或删除

**存储建议**：

- 表名：`purchase_order`
- 主键：`order_id`
- 外键：
  * `supplier_id → supplier_info.supplier_id`
  * `item_id → item_master.item_id`
- 索引：`(supplier_id, purchase_date, status)`
- 分区：按 purchase_date 月度分区
