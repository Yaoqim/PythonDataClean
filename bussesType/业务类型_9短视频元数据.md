### 七、短视频元数据

**数据特征**：结构化，中等量级，相对简单

**业务字段清单**：video_id, title, description, author_id, publish_time, view_count, like_count, share_count, duration

**业务核心字段**：video_id(主键), title, description, author_id, publish_time, view_count

##### 字段详细说明表

| 英文字段名   | 中文名   | 来源性质 | 处理方式                             | 说明         |
| ------------ | -------- | -------- | ------------------------------------ | ------------ |
| video_id     | 视频 ID  | 原始     | 保留纯字母数字                       | 视频唯一标识 |
| title        | 标题     | 原始     | 去特殊字符、统一编码、截断 200 字    | 视频主题     |
| description  | 描述     | 处理后   | 去 HTML、特殊符、截断 2000 字        | 视频简介     |
| author_id    | 作者 ID  | 原始     | 保留纯数字，缺失填充"匿名"           | 作者唯一标识 |
| publish_time | 发布时间 | 处理后   | 相对 → 绝对时间，YYYY-MM-DD HH:MM:SS | 发布时刻     |
| view_count   | 播放量   | 处理后   | 去单位，换算整数                     | 播放次数     |
| like_count   | 点赞数   | 处理后   | 去单位，换算整数，检测异常           | 点赞次数     |
| share_count  | 转发次数 | 处理后   | 去单位，转整数                       | 转发次数     |
| duration     | 时长     | 处理后   | 转整数，单位秒                       | 视频时长     |

##### 特殊字段处理说明

**1. 时长格式转换**

- 若 parent_comment 存在性检查失败，执行 30% 的准确度的渐进
Duration Formats:
  "5:30" -> 330 seconds
  "330 seconds" -> 330 seconds
  "5 min 30 sec" -> 330 seconds

Range Check: duration > 0, duration < 86400 (24 hours)

**2. 互动数异常检测**

- 若 parent_comment 存在性检查失败，执行 30% 的准确度的渐进
Anomaly Detection:
  like_count > 1000000: flag as abnormal
  share_count > like_count * 10: flag as abnormal
  view_count = 999999: likely default value, flag

##### 新增标记字段

| 字段名          | 类型   | 用途                                                                                     |
| --------------- | ------ | ---------------------------------------------------------------------------------------- |
| is_cleaned      | 布尔   | 是否已清洗(0/1)                                                                          |
| abnormal_tag    | 字符串 | 异常标记(encoding_error/duration_invalid/view_count_abnormal/like_count_abnormal/normal) |
| engagement_rate | 浮点   | 互动率 = (like_count + share_count) / view_count                                         |
| clean_time      | 时间   | 清洗完成时间                                                                             |

**常见问题与清洗方案**：

##### 分步骤清洗流程

**第一阶段：去重与关键字段验证**

| 问题类型 | 具体表现 | 清洗方案 | 执行步骤 | 无法清洗处理 |
| --- | --- | --- | --- | --- |
| 重复视频 | 同一 video_id 在不同时间抓取 | 按 video_id 去重，保留互动数(view_count)最高的记录 | 1. 按 video_id 分组 2. 比较互动数 3. 保留峰值记录 | 若无 view_count，保留最新抓取记录 |
| video_id 缺失 | 视频无唯一标识 | **补充策略**：由(author_id, title, duration, publish_time)组合生成 MD5 哈希 ID | 1. 组合关键字段 2. 生成 16 位哈希 3. 校验唯一性 | 关键字段缺失 > 2 个 -> 标记 "critical_missing" -> 删除 |
| author_id 缺失 | 无法关联作者 | **补充策略**：从视频描述中正则提取作者 ID 或昵称反查 | 1. 正则匹配描述中的 ID 2. 若有 author_name，查历史库 3. 标记 "author_supplemented" | 无法补充 -> 填充 "anonymous" -> 标记 "user_unknown" |

**第二阶段：字段内容清洗与补充**

| 问题类型 | 具体表现 | 清洗方案 | 执行步骤 | 准确性评估 | 无法清洗处理 |
| --- | --- | --- | --- | --- | --- |
| 时长格式混乱 | "5:30" / "330s" / "5分30秒" | 统一转换为 "秒" (整数) | 1. 识别时间格式 2. 按规则换算为秒 3. 标记原始格式 | 转换准确率 > 99% | 无法识别 -> 从 description 提取 -> 仍失败则标记 "duration_invalid" |
| 标题/描述污染 | 包含营销链接、刷屏符号 | 去除特殊符号、表情、营销链接 | 1. 正则去 URL 2. 清理特殊 Unicode 字符 3. 截断超长部分 | 清洗后长度 > 0 且语义可读 | 全是乱码/符号 -> 标记 "content_invalid" -> 删除 |
| 描述缺失 | description 为空 | **补充策略**：从视频标题或标签(tags)中提取关键词补全 | 1. 提取 title 关键词 2. 组合为简短描述 3. 标记 "desc_generated" | 补充内容相关度评分 | 保持为空，标记 "desc_missing" |

**第三阶段：异常值检测与修正**

| 问题类型 | 具体表现 | 清洗方案 | 执行步骤 | 异常判定标准 | 无法清洗处理 |
| --- | --- | --- | --- | --- | --- |
| 播放量异常 | 999999 (默认填充值)、负数 | 逻辑校验，默认值置为 0 | 1. 范围校验(>=0) 2. 检测常见默认填充值 3. 标记异常 | view_count < 0 或为常见占位符 | 无法确定 -> 标记 "view_count_abnormal" |
| 互动比例异常 | share_count > view_count | 异常比例拦截，标记疑似刷量 | 1. 计算 share/view 比例 2. 比对行业阈值 3. 标记异常 | share_count > view_count * 1.5 | 标记 "engagement_fraud_suspicious" |
| 时长极短 | duration < 1s | 标记为无效视频或广告片段 | 1. 校验时长 2. <1s 则标记 3. 联动描述判断是否为广告 | duration < 1s | 标记 "video_too_short" -> 删除 |

**第四阶段：文本清洗与编码处理**

| 问题类型 | 具体表现 | 清洗方案 | 执行步骤 | 验证方式 | 无法清洗处理 |
| --- | --- | --- | --- | --- | --- |
| 编码乱码 | title/desc 出现 GBK 转 UTF-8 损坏 | 尝试自动修复常见乱码模式 | 1. 识别乱码特征 2. 尝试多次重新编码 3. 语义校验 | 汉字占比 > 80% | 无法修复 -> 标记 "encoding_error" -> 删除 |

##### 缺失值补充策略汇总

| 缺失字段 | 一级补充(>95%) | 二级补充(70-95%) | 外部补充(<70%) | 补充失败处理 |
| --- | --- | --- | --- | --- |
| **video_id** | 原始系统 ID | (author_id+title)哈希 | 抓取序号 | **无法补充** -> 删除 |
| **duration** | 元数据时长字段 | 描述文本正则提取 | 视频帧数换算 | 标记 "duration_unknown" |
| **author_id** | 原始系统作者 ID | 作者昵称反查库 | 填充 "anonymous" | 标记 "author_missing" |
| **publish_time** | 原始发布时间戳 | 相对时间(如3小时前)换算 | 抓取时间 | 标记 "time_estimated" |

**准确性评估指标**：

- 若 parent_comment 存在性检查失败，执行 30% 的准确度的渐进
video_quality = Σ(field_weight × field_confidence) / Σfield_weight

字段权重分配：
  video_id: 1.0 (必填)
  title: 0.9 (核心)
  author_id: 0.8 (关键)
  duration: 0.7 (重要)
  publish_time: 0.8 (重要)
  view_count: 0.4 (辅助)

判定标准：
  >= 85%: 优质元数据，可直接用于分析
  >= 60%: 合格数据，需带标记使用
  < 60%: 低质数据，建议剔除


**存储建议**：

- 表名：`short_video_metadata`
- 主键：`video_id`
- 索引：`(author_id, publish_time, view_count)`
