####  电商商品信息

**业务字段清单**：product_id, source_platform, title, price, original_price, currency_code, brand, spec_params, sales_volume, comment_count, rating, good_rate, shop_name, shop_id, is_official, listing_time, update_time

**关键字段准确度评估机制说明**

为了量化数据清洗的有效性，本项目为每个关键字段建立了准确度评估机制。当关键字段缺失时，通过其他数据源的推导或分析方法补充数据，同时需要评估补充后数据的可信度。

##### 多币种价格转换处理方案

**场景识别**：

抓取数据可能为：
  price: "$99.99" (美刀)
  or "€79.50" (欧元)
  or "¥599" (人民币)
  or "8999RMB"

**处理流程**：

1. **货币识别**

   - 提取货币符号或代码：$→USD, €→EUR, ¥→CNY 等
   - 记录到`currency_code`字段用于审计

2. **单位统一**

   - 去除货币符号和文字单位
   - 提取数字部分转为 float

3. **汇率转换**（如需转 RMB）

   ```python
   # 示例汇率配置（需定期维护）
   exchange_rates = {
       "USD": 7.08,   # 1美元 = 7.08人民币
       "EUR": 7.75,   # 1欧元 = 7.75人民币
       "GBP": 8.95,   # 1英镑 = 8.95人民币
       "JPY": 0.048,  # 1日元 = 0.048人民币
       "CNY": 1.0     # 已是人民币
   }
   # 转换逻辑
   price_rub = price_value * exchange_rates.get(currency_code, 1.0)
   
4. **异常处理**

   - 无法识别的货币 → 标记"currency_error"，保留原始价格
   - 汇率过期 → 标记"exchange_rate_outdated"
   - 价格为 0 或负数 → 标记"price_invalid"

5. **数据质量标记**
    字段: price_currency_info
   值示例: {
     "original_currency": "USD",
     "original_price": 99.99,
     "exchange_rate": 7.08,
     "converted_price_cny": 707.91,
     "conversion_date": "2024-01-08",
     "is_converted": true
   }
**数据库字段补充**：

| 字段名              | 类型       | 说明                         |
| ------------------- | ---------- | ---------------------------- |
| price               | Float      | 最终价格(已转 RMB，若需要)   |
| original_price      | Float      | 原始列表价格                 |
| currency_code       | Varchar(3) | 原始货币代码(USD/EUR/CNY 等) |
| price_currency_info | JSON       | 完整转换信息(含汇率/时间等)  |
| is_price_converted  | Boolean    | 是否已进行汇率转换           |

**常见问题与清洗方案**：

##### 分步骤清洗流程

**第一阶段：去重与关键字段验证**

| 问题类型        | 具体表现                      | 清洗方案                                                                                           | 执行步骤                                                               | 无法清洗处理                                                        |
| --------------- | ----------------------------- | -------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- | ------------------------------------------------------------------- |
| 重复数据        | 同一 product_id 出现多次      | 按 product_id 去重，保留 update_time 最新的                                                        | 1. 按 product_id 分组 2. 统计重复数量 3. 保留 update_time 最大值       | 若无 update_time，按抓取时间保留最后一条                            |
| 缺失关键字段    | product_id、price、title 为空 | **准确性评估**：缺失必填字段无法补充 → 标记"critical_missing" → 删除记录                           | 1. 检验必填字段列表 2. 标记缺失类型 3. 删除无法补充的记录              | 直接删除，无补充途径                                                |
| product_id 缺失 | 商品无唯一标识                | **补充策略**：尝试由(source_platform, shop_id, title, listing_time)组合生成哈希值作为临时 ID       | 1. 组合字段生成哈希 2. 检验哈希唯一性 3. 添加标记"id_generated"        | 若组合字段也缺失或冲突，标记"id_supplement_failed"，待人工审核      |
| price 缺失      | 商品无价格信息                | **补充策略**：① 查询同店铺同品牌同类别商品的平均价格 ② 查询历史版本数据 ③ 标记"price_supplemented" | 1. 查同店/同品牌/同类别商品 2. 获取价格中位数 3. 补充价格并标记来源    | 无相似商品参考 → 标记"price_unavailable" → 按业务需求决定删除或保留 |
| title 缺失      | 商品无标题                    | **补充策略**：① 从品牌标准库生成标题 ② 查询历史版本数据                           | 1. 查询品牌标准库生成标题 2. 标记"title_generated" 3. 手动验证         | 无品牌信息 → 标记"title_unavailable" → 删除或待审核                  |

**第二阶段：字段内容清洗与补充**

| 问题类型       | 具体表现                    | 清洗方案                                                      | 执行步骤                                                                           | 准确性评估                                                                                                              | 无法清洗处理                                                           |
| -------------- | --------------------------- | ------------------------------------------------------------- | ---------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| 多币种价格     | $99.99 / €79.50 / ¥599      | 识别货币类型 → 查询汇率表 → 转换为 RMB                        | 详见"多币种价格转换处理方案"                                                       | **准确性检验**：① 汇率来源可靠性(央行汇率>99.5%) ② 转换日期与数据日期不超过 7 天 ③ 转换后价格合理性检验(不超出品类范围) | 无汇率或汇率过期>30 天 → 标记"exchange_rate_unavailable" → 保留原币种  |
| 标题内嵌标记   | 【官方旗舰店】iPhone 15 Pro | 从 title 提取平台标记，通过 is_official 字段标记               | 1. 正则匹配【】内容 2. is_official 置 1 3. 更新 title               | 检验提取是否完整，is_official 是否有效                                                                                    | 提取错误 → 保留原始 title，标记"tag_extract_error"                     |
| 规格参数不完整 | 技术类商品缺少关键参数      | **补充策略**：① 查同品牌同型号商品的规格 ② 从品牌官网爬取参数 | 1. 解析 spec_params JSON 2. 检验关键字段 3. 补充缺失参数 4. 评估 spec_completeness | **准确性评估**：补充参数的置信度评分(0-100%)：官网>99%, 同品牌>85%, 其他>60%                                            | 无法从其他源获取 → spec_completeness 评分 <70% → 标记"spec_incomplete" |
| 单位混乱       | 销量"1.5 万件"、"15000 件"  | 提取数字部分 → 单位转换(万 →\*10000) → 转整数                 | 1. 正则提数字 2. 识别单位 3. 单位转换 4. 转整数                                    | 转换结果是否合理(销量范围检验)                                                                                          | 无法识别单位格式 → 保留原始值，标记"sales_volume_invalid"              |

**第三阶段：异常值检测与修正**

| 问题类型   | 具体表现                  | 清洗方案                           | 执行步骤                                                    | 异常判定标准                 | 无法清洗处理                                           |
| ---------- | ------------------------- | ---------------------------------- | ----------------------------------------------------------- | ---------------------------- | ------------------------------------------------------ |
| 评分异常   | 5.5 分、0 分、-1 分、9 分 | 范围检验(0-5) → 超出范围则标记异常 | 1. 检验范围 2. 异常值标记"rating_invalid" 3. 可选删除或标记 | 标准范围 0-5，精度 0.1       | 无法确定正确值 → 标记"rating_unknown" → 根据好评率反推 |
| 好评率异常 | 120%、-50%、0%            | 范围检验(0-100%) → 超出范围标记    | 1. 检验范围 2. 若为百分比字符串先转数字 3. 标记异常         | 标准范围 0-100%              | 若为 0% → 检验是否真实(是否有评论)，为真实则保留       |
| 时间异常   | 时间早于商品上架时间      | 比对 publish_time 和 listing_time  | 1. 比对两个时间 2. 若早于上架时间标记异常                   | publish_time >= listing_time | 时间无法修正 → 标记"time_invalid"                      |

**第四阶段：文本清洗与编码处理**

| 问题类型 | 具体表现                 | 清洗方案                             | 执行步骤                                     | 验证方式                | 无法清洗处理                                       |
| -------- | ------------------------ | ------------------------------------ | -------------------------------------------- | ----------------------- | -------------------------------------------------- |
| 特殊字符 | 商品名含"❌""⚠️"等 emoji | 去除特殊字符和 emoji，保留中英文数字 | 1. 检测 emoji 和特殊符号 2. 删除 3. 验证结果 | 清洗后文本长度>0 且可读 | 全是特殊字符无实际内容 → 标记"title_invalid"       |
| 超长文本 | 商品名>500 字            | 截断至 200 字                        | 1. 检测长度 2. 超长则从前截断至 200 字       | 截断后是否包含完整信息  | 自行评估是否需要保留全文                           |
| 乱码问题 | 商品名出现乱码           | 尝试 chardet 库检测编码 → 重新解码   | 1. chardet 检测编码 2. 重新解码 3. 验证      | 解码后无乱码且可读      | 编码无法识别 → 标记"encoding_error" → 删除或待审核 |

##### 缺失值补充策略汇总

**分级补充方案**（按准确性从高到低）：

| 缺失字段        | 一级补充(高置信度>95%)               | 二级补充(中置信度 70-95%)     | 外部补充(低置信度<70%) | 补充失败处理                                |
| --------------- | ------------------------------------ | ----------------------------- | ---------------------- | ------------------------------------------- |
| **product_id**  | 源系统提供的备用 ID                  | 生成(platform+shop+title)哈希 | 使用内部序列号         | **无法补充** → 删除记录                     |
| **price**       | 当前时间段数据库同品牌同店铺商品     | 历史版本数据                  | 同分类平均价           | **标记 price_unavailable** → 按需删除或保留 |
| **title**       | 历史版本数据                         | 品牌官网+分类生成             | 分类+型号生成          | **标记 title_unavailable** → 删除或审核     |

| **spec_params** | 品牌官网规格                         | 同型号商品规格库              | 通用规格库             | **标记 spec_incomplete** → 评分<70%         |
| **shop_id**     | 源系统 shop_id                       | 店铺名查询店铺库              | 无法补充               | **标记 shop_unknown** → 保留 shop_name      |
| **good_rate**   | 从评论数据计算(comment 表 rating>=4) | 从 rating 反推                | 无法补充               | **标记 good_rate_unknown** → 留空           |

**准确性评估指标**（多维度综合评分）：

准确性评分公式：
  accuracy_score = \sum (field_weight × field_confidence) / \sum field_weight

其中：
  - field_weight：字段重要性权重(必填字段权重 1.0，可选字段 0.5)
  - field_confidence：每个字段的置信度(0-100%)

判定标准：
  accuracy_score >= 85%：数据质量优秀，可直接使用
  accuracy_score >= 70%：数据质量良好，可使用但需标记
  accuracy_score >= 50%：数据质量一般，需要审核后使用
  accuracy_score < 50%：数据质量差，不建议使用或删除

) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='电商商品信息表';

##### 关联标签表结构

```sql
CREATE TABLE ec_product_info_tag (
  -- 复合主键
  product_id VARCHAR(100) NOT NULL COMMENT '商品ID',
  tag_value VARCHAR(100) NOT NULL COMMENT '标签值',
  
  -- 标签置信度
  tag_confidence INT NOT NULL COMMENT '标签置信度(0-100)',
  
  -- 元数据
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '标签创建时间',
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '标签更新时间',
  
  -- 主键和外键
  PRIMARY KEY (product_id, tag_value),
  FOREIGN KEY (product_id) REFERENCES ec_product_info(product_id) ON DELETE CASCADE ON UPDATE CASCADE,
  
  -- 索引
  KEY idx_tag_value (tag_value),
  KEY idx_confidence (tag_confidence)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='电商商品标签表';
```

##### 字段类型与约束说明

| 字段分类 | 描述 |
|---------|------|
| 业务核心字段 | title、price、currency_code、shop_name、source_platform（五个核心字段）必填，每个核心字段都有对应的准确度评估字段(_anal、_anal_info) |
| 业务核心字段准确度评估 | 每个核心字段需有：{field}_anal（准确度评分0-100）、{field}_anal_info（评估说明）两个配套字段 |
| 价格相关 | price 使用 DECIMAL(12,2) 以保证精度，支持多币种转换 |
| 时间相关 | listing_time、update_time 统一使用 YYYY-MM-DD HH:MM:SS 格式 |
| JSON字段 | spec_params、price_currency_info 用于存储复杂结构数据 |
| 评分字段 | rating 范围 0-5，good_rate 范围 0-100%，spec_completeness 范围 0-100% |
| 清洗标记 | abnormal_tag 用于标记数据异常情况 |
| 标签关联 | 通过 ec_product_info_tag 表实现多值标签存储，支持高效查询 |
